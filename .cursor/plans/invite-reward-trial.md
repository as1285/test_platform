# 邀请有礼 · 方案 1 定稿（拉人兑时效激活）

> 状态：产品规则已确认，待排期开发  
> 更新：2026-07-22

## 目标

用「邀请成功 → 返还可用时长」降低对 199 永久激活的抵触，促进分享裂变。  
**不发现金、不发永久免费码；被邀请人不给体验时长。**

## 已确认产品规则

| 项 | 规则 |
|----|------|
| 计奖条件 | 被邀请人完成 **注册 + 首次激活成功**，且归因到邀请人 |
| 邀请人奖励 | **+7 天** 时效使用权（可叠加） |
| 被邀请人 | **不给** 体验天数；需自行购买激活码 / 走现有付费路径 |
| 月封顶 | 默认 **4 次/月**（约 28 天），**管理后台可配置** |
| 已永久用户 | 邀请成功可发「可转赠 7 天码」或只记次数（实现时二选一，默认：发可转赠时效码） |
| 到账延迟 | 首次激活后 **48 小时** 再发奖（可后台配置） |
| 分销层级 | 仅奖励 **直接邀请人**，不做多级 |

### 后台可配置项（运营）

建议进「系统设置 / 邀请有礼」：

- `invite_reward_days`：每次奖励天数，默认 `7`
- `invite_monthly_cap`：每月最多计奖次数，默认 `4`
- `invite_grant_delay_hours`：发奖延迟小时，默认 `48`
- `invite_enabled`：总开关，默认关，灰度时打开

## 技术要点（摘要）

1. **时效激活底座**：`activation_kind`（none/trial/permanent）+ `active_until`；鉴权统一 helper。  
2. **邀请归因**：每人 `invite_code`；注册写 `invited_by`（只写一次）；分享链接/二维码带 invite。  
3. **发奖流水**：`user_invites`（pending → granted / rejected）+ 可选 `activation_grants`。  
4. **激活码**：支持 `grant_days`（NULL=永久）；邀请主路径优先直接给邀请人 +N 天。  
5. **防刷**：同设备作被邀请人最多计奖 1 次；禁止自邀；月封顶；延迟发奖；后台可作废。

## 分期

| 阶段 | 内容 | 验收 |
|------|------|------|
| **A** | 时效激活字段 + 鉴权改造 +「我的」剩余天数；后台可发 N 天体验码（运营补发用，**非**被邀请人默认礼） | 体验码到期自动失效；永久用户不变 |
| **B** | 邀请码/分享图、注册归因、激活计奖、48h 发奖、月封顶、后台配置项 | A 邀 B 注册并激活 → 48h 后 A +7 天；自邀/超封顶不发 |
| **C** | 分享图打磨、邀请漏斗报表、参数调优 | 可看点击→注册→激活→发奖漏斗 |

## 明确不做

- 现金返佣  
- 被邀请人自动体验  
- 多级分销  
- 用永久激活码当拉人奖励  

## 成功指标（试跑 2–4 周）

- 邀请归因可核对  
- 刷量拦截有效  
- 199 永久购买量不明显下滑  
- 邀请人能看懂剩余天数与本月已用次数  

## 下一步

确认排期后按 **Phase A → B** 开工；C 可在小流量验证后再做。
