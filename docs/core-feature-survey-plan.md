# 核心功能调研计划

> 覆盖价格、功能使用、用户疑难；点选疑虑时当场给出合理解释。  
> 文档版本：2026-08-28  
> 调查文件：`frontend/public/js/surveys/*.json`

---

## 一、目标

1. **收数**：每个核心功能只问一次（每账号 1 条），问清价格感受、好不好用、卡在哪。
2. **解释**：用户点「怕不是正式的 / 怕白花钱 / 怕和官方冲突」时，立刻给出简短、诚实的说明，而不是只记一笔吐槽。
3. **不打扰**：同一会话最多弹 1 次离开问卷；点遮罩或「这次先不说」本会话不再弹。

现有三套问卷（支付页价格、证明页价格/体验、个税填写满意度）各自为政。本计划先统一**调查文件**，再按阶段接到同一套引擎。

---

## 二、调查文件约定

每个功能一份 JSON，字段如下。

| 字段 | 含义 |
|------|------|
| `id` | 功能键，与埋点 `product` / 后台菜单对应 |
| `title` / `page` | 中文名、C 端页面 |
| `phase` | 落地批次：`live` 已上线、`1` 先改现有页、`2` 再铺演示工具 |
| `trigger` | `exit` 离开拦截 / `card` 页内卡片 / `both` |
| `price` | 标价、偏贵/合适/偏便宜、心理价筹码 |
| `usage` | 满意度、最想优化芯片 |
| `concerns[]` | 疑虑芯片 + `explain`（给用户看的解释） |
| `suggestion` | 选填原文，最长 500 字 |

点疑虑后：先展示 `explain`，再继续收价格/满意度。解释必须诚实——演示样例不能说成官方文书。

## 四、三块问题（所有功能共用结构）

### 1. 价格

- 态度：偏贵 / 合适 / 偏便宜（点完即可走）
- 偏贵或偏便宜时再点心理价筹码
- 开通套餐筹码偏高档（约 ¥50–198）；证明 ¥50；社保演示约 ¥199

### 2. 功能使用

- 满意度：满意 / 一般 / 不满意
- 最想优化：按页面写芯片（填写、导入、预览、分享保存、支付、计算等）
- 选填一句建议

### 3. 疑难担忧 + 当场解释

每个功能 4～6 条高频担心。点中后展示 `explain`，例如：

- 「怕不能当正式材料」→ 明确是演示样例，正式用途走官方渠道
- 「怕和个税 APP 对不上」→ 口径对齐累计预扣，但不是申报通道
- 「怕付了还带水印」→ 到账后去水印；未到账先刷新本页
- 「怕主套餐还要再付钱」→ 写清哪些是独立加购

解释只消除误解，不承诺官方效力。

## 五、落地顺序

**第 1 批（先改已上线页）**

1. 调查文件作为唯一文案源（本目录 JSON）。
2. 支付页 / 证明页 / 填写页：点疑虑后展开解释，再收价格或建议。
3. 填写页补「开通价感觉」选填，与支付页调研去重（已填支付调研则不再问套餐价）。

**第 2 批（演示工具）**

社保演示、完税码、工资流水按同一 JSON 接离开问卷；公积金以核验页轻问为主。

**第 3 批（后台）**

数据分析增加「功能调研」总览：按功能看偏贵%、不满意%、疑虑 Top、建议原文。现有「支付分析 / 填写调研 / 证明统计」可先继续用，再合并。

**已落地（2026-09-07）**：产品洞察 → 功能调研。已接线开通套餐 / 个税填写 / 离职与在职证明；疑虑芯片未落库，表内用「最想优化」作 Top。社保 / 完税码 / 流水 / 公积金仍显示 C 端未接。

## 六、体验与频控

- 每账号 × 每功能最多 1 条正式提交
- 离开问卷：点选项约 2 秒自动离开；写建议时不自动走
- 软关闭只记本会话，不写「跳过」污染满意度
- 未登录不弹
- 底部导航切走不拦，只拦返回键 / 系统后退（填写页已如此）

---

## 七、验收

- JSON 能通过 `surveys/validate.js`（结构、解释非空、价格筹码合法）
- 每个 `concerns[].explain` 可单独给用户看，不依赖运营口头补充
- 第 1 批三页：点任一疑虑能看到解释，提交仍进现有表或统一表
