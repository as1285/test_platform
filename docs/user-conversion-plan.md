# 用户转化与留存规划

> 从下载页 → 安装 → 注册 → 激活 → 填写个税 → 持续使用  
> 基于 `test_platform` 现有能力与埋点整理，供产品与研发排期参考。  
> 文档版本：2026-05-28

---

## 一、现状速览（项目已有能力）

| 阶段 | 现有触点 | 可观测数据 |
|------|----------|------------|
| 下载/安装 | `install_guide.html`、公开接口 `install-packages`、浏览器访问时 `browser-install-prompt.js` | 安装页访问、下载点击（可补埋点） |
| 注册 | `register.html` → `auth.php?action=register` | `EVENT register_success`、渠道字段 `register_source_channel` |
| 激活 | `mine.html` 激活弹窗、`consult.html` | `track_activate_prompt_*`、后台「注册转化率」= 当日激活 ÷ 注册 |
| 填个税 | `consult.html` 税务记录 Tab、批量添加、任职 `renzhi.html` | `tax_records` 有无、「用户行为」未填个税 cohort |
| 留存/意愿 | 首页、办查、收入明细、消息等 | `user_page_events`、未填个税用户的停留/路径 |

**关键事实（用户行为分析）：** 大量用户会逛「我的 / 个人中心 / 收入纳税明细」，但**没有个税记录**——卡点更可能在**动机、信任、步骤成本、激活前被挡住**，而不只是「找不到入口」。

## 二、目标漏斗与核心指标

### 漏斗示意

```mermaid
flowchart LR
  A[访问安装页] --> B[完成安装/打开APP]
  B --> C[注册成功]
  C --> D[24h内激活]
  D --> E[7天内有个税记录]
  E --> F[7天内查看收入明细]
  F --> G[30日回访/再次编辑]
```

### 指标定义（建议统一口径）

| 指标 | 定义 | 说明 |
|------|------|------|
| 安装转化 | 安装页 UV → 首次打开 APP（或首次 `index`/`login`） | 按渠道分别统计 |
| 注册转化 | 打开 APP → `register_success` | iOS / Android 分开 |
| 激活转化 | 注册 → 24h 内 `account_active=1` | 对齐后台「日转化率」 |
| **个税填写转化** | 已激活 → 7 天内 `tax_records` ≥ 1 | **建议新增核心 KPI** |
| 价值感知 | 有个税记录 → 打开「收入纳税明细」 | 证明「填了有用」 |
| 留存 | D7 / D30 有页面行为或登录 | 按 cohort 观察 |

### 后台建议

在「数据统计」扩展或新增看板：**注册 → 激活 → 有个税 → 看过明细** 四段漏斗，按 `register_source_channel` / `activation_source_channel` 拆分（渠道分析已有基础）。

**建议新增两个运营指标（需开发统计）：**

- **激活后 7 日个税填写率** = 7 天内有个税记录的用户 ÷ 当日激活用户  
- **填写后 7 日明细查看率** = 打开过收入纳税明细的用户 ÷ 有个税记录用户

## 三、分阶段用户旅程规划

### 阶段 0：下载前（站外 / 安装页）

**目标：** 降低「下完不会装、装完打不开」的流失。

- **安装页**（`install_guide.html` / 外站 installguide）：  
  - 首屏只保留 2 个主按钮：Android APK、iOS 描述文件 + **「3 步完成」** 图文/视频。  
  - 每步下方加 **「装好后点这里注册」** 深链到 APP 注册页（Universal Link / 自定义 scheme，能做多做）。  
- **埋点补齐：** `track_install_apk_click`、`track_install_ios_click`、`track_install_video_play`（安装页前端事件，与 API 统计互补）。

---

### 阶段 1：安装后首次打开（D0，0～10 分钟）

**目标：** 10 分钟内完成「注册 + 知道要激活 + 知道填个税能看什么」。

| 动作 | 建议 |
|------|------|
| 首屏 | 未登录 → 注册页；已注册未激活 → **强引导激活**（`mine` 弹窗可改为不易跳过的 3 步向导） |
| 价值预告 | 注册成功不要只进 `mine.html`：用 **1 屏引导**「激活后可生成收入纳税明细 / 证书样式记录」+ 示意图（保留非官方声明） |
| 降低迷惑 | README 已写演示性质；APP 内用 **短文案** 再说明一次，避免用户以为要连真税局 |

**产品形态：「新手任务」3 项**

1. 激活账号  
2. 添加 1 条任职（`renzhi.html` / `GET user.php#employers`）  
3. 添加 1 条税务记录（`consult.html` 税务记录 Tab）  

完成一项给进度反馈（进度条即可，不必复杂积分）。

---

### 阶段 2：注册 → 激活

**目标：** 提高 `track_activate_prompt_confirm` ÷ 注册数。

| 问题假设 | 对策 |
|----------|------|
| 不知道要激活 | 注册成功页直接进入 **激活向导**，而非静默进「我的」 |
| 没有激活码 | 强化 **闲鱼购买 / QQ**（已有 `track_xianyu_purchase_click`），弹窗内「复制文案 + 一键跳转」 |
| 想先逛逛 | 允许浏览，但 **核心功能上锁**（收入明细、批量添加、证书预览），点击时说明「需激活」 |
| 激活后无下一步 | 激活成功 → **自动跳转「示例填写」或一键导入样例数据** |

**运营：** 保留「注册转化率」；可增加 **「注册后 24h 未激活」用户列表**（人工/客服跟进，若业务允许）。

---

### 阶段 3：激活 → 填写个税

**目标：** 把「会逛 App」变成「有个税记录」。

结合 **未填个税用户行为**（常去：我的、办查、消息、个人中心，但无 `tax_records`）：

| 策略 | 说明 |
|------|------|
| **默认路径** | 激活成功 → 直达 `consult.html` 税务记录 Tab 或「批量添加」向导，而非仅首页 |
| **示例数据** | 强化「示例填写」首屏 + 文案：「30 秒体验完整明细」 |
| **分步降负** | 第一步只填：公司 + 1 个月工资；第二步再专项扣除 |
| **任职与个税联动** | `renzhi.html` 保存任职后提示：「去生成对应月份纳税记录」并带跳转 |
| **空状态优化** | `shuiming` / 收入明细空页：大图 + 「去添加第一条记录」+ 短操作演示 |
| **放弃挽回** | 2 次进入收入明细仍无记录 → 轻提示「需先在个人中心添加税务记录」 |

**避免：** 未填个税时堆过多支线入口；先 **单主线**。

---

### 阶段 4：填完个税 → 价值确认

**目标：** 让用户感到「填这一遍有回报」，提高 7 日留存。

| 时刻 | 设计 |
|------|------|
| 保存成功 | 立刻跳转 **收入纳税明细** 或 **纳税记录证书预览**（`najilu` 等） |
| 自用/展示 | 「保存图片 / 分享预览」（保留演示免责声明） |
| 可编辑暗示 | 「可随时在我要咨询里修改」减少「填错不敢动」 |
| 二次使用 | 首页卡片：「查看去年汇总」等轻提醒 |

---

### 阶段 5：持续使用与意愿维护（30 天+）

**目标：** 需要时想得起、敢打开，而非强制日活。

- **轻触达：** 消息中心放「数据维护提醒」（演示向，非真实申报截止）  
- **版本更新：** `about_update` 说明新功能，引导老用户补数据  
- **关怀版：** `care_version.html` 对「只看不填」用户可默认简化导航  
- **反馈闭环：** `feedback` → 后台回复，提升信任  

**不建议：** 过度推送或模仿官方催申报话术（合规与信任风险）。

## 四、按优先级的产品路线图

### P0（约 2～4 周，直接抬转化）

1. **注册/激活后固定动线**：注册 → 激活向导 →（激活成功）→ 税务记录 Tab / 示例填写  
2. **未激活能力边界清晰**：可浏览首页，不可看明细/批量添加  
3. **空状态与一条主线 CTA**（收入明细、我的页）  
4. **后台漏斗看板**：注册 → 激活 → 有个税（7 天）→ 看过明细  

### P1（约 1～2 月）

5. **新手任务 3 步 + 进度**（激活 / 任职 / 税记录）  
6. **安装页与 APP 埋点统一**（下载点击、视频完播）  
7. **分渠道转化报告**（闲鱼码、QQ、自然注册）  
8. **未填个税分群运营**（后台导出 + 话术模板）  

### P2（长期）

9. **智能引导**：根据 `user_page_events` 识别「只逛不填」→ 一次性针对性引导  
10. **场景模板**：「上班族 1 年公司 12 个月」一键生成  
11. **A/B 测试**：激活弹窗文案、示例填写位置等

## 五、运营复盘节奏（建议每周）

| 看什么 | 在哪 | 决策 |
|--------|------|------|
| 注册 vs 激活 | 数据统计 → 注册转化率 | 改激活码触达/弹窗 |
| 渠道质量 | 渠道分析 | 加大高「有个税率」渠道投入 |
| 填个税卡点 | 用户行为 → 未填个税 | 看 TOP 页面，改对应页 CTA |
| 激活弹窗 | 接口统计 `track_activate_prompt_*` | 改文案/步骤 |
| 单用户诊断 | 用户行为 → 路径 | 客服复现用户困惑 |

## 六、内容与信任（贯穿全 funnel）

1. **演示定位一句话**：安装页、注册页、关于页一致——「界面演示 / 学习参考，非官方申报」。  
2. **降低顾虑**：强调数据可改、可删（与技术能力一致时）。  
3. **激活码价值**：说明是「解锁完整演示数据能力」，而非模糊收费。  
4. **成功可视化**：证书/明细截图放在激活成功页（已有渲染能力）。

## 七、90 天成功标准（需先拉一周 baseline）

| 阶段 | 方向性目标 |
|------|------------|
| 注册 → 24h 激活 | 较 baseline +15%～25% |
| 激活 → 7d 有个税 | 较 baseline +20%～30% |
| 有个税 → 7d 看明细 | > 70% |
| 未填个税占注册存量比 | 持续下降 |

## 九、接口与埋点速查

| 名称 | 含义 |
|------|------|
| `GET user.php#employers` | 接口统计用 `route_key`，实际为 `GET /api/user.php?action=employers`（任职列表）；页面多为 `renzhi.html` 或 `consult.html` 任职 Tab |
